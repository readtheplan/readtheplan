# Example: Agent Gate in CI/CD

This example demonstrates how to integrate `readtheplan agent-gate` into a GitHub Actions workflow.

## Overview

The `agent-gate` command is designed for coding agents and CI/CD pipelines. It provides a structured JSON contract (`rtp-agent-gate-v1`) that includes:

- **Decision**: `proceed`, `warn`, or `block`.
- **Reason**: A human-readable explanation of the decision.
- **Next Actions**: Explicit lists of `allowed_next_actions` and `prohibited_next_actions`.
- **PR Comment**: A pre-formatted Markdown summary that avoids raw plan JSON. Review it before posting to public PRs because resource addresses can still reveal environment details.

## Files

- `agent-gate.json`: An example of the JSON output generated by `readtheplan agent-gate`.
- `github-actions.yml`: A sample GitHub Actions workflow demonstrating how to parse the decision and enforce the gate.

## Local Usage

You can run the agent gate locally on any Terraform plan JSON file:

```bash
readtheplan agent-gate plan.json
```

To include compliance-specific checks (e.g., SOC2):

```bash
readtheplan agent-gate --framework soc2 plan.json
```

## CI Integration Strategy

1. **Plan Generation**: A trusted workflow runs `terraform plan -out=tfplan` and `terraform show -json tfplan > plan.json`.
2. **Artifact Storage**: The `plan.json` is stored as a build artifact.
3. **Agent Gate**: This workflow downloads the `plan.json`, runs `readtheplan agent-gate`, and uses the `decision` field to determine if the pipeline should continue or fail.
4. **Safe Reporting**: Use the `pr_comment` field for a GitHub Actions step summary or reviewed PR feedback without exposing the full, potentially sensitive, Terraform plan JSON.
