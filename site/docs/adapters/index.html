Docs / Adapters

Adding a new IaC adapter.

readtheplan's adapter system lets you plug in support for any infrastructure-as-code tool — Pulumi, CDK, Crossplane, or custom in-house tooling. This guide walks through the full process, from the BaseAdapter interface to an end-to-end worked example.

What are adapters?

An adapter translates a specific IaC tool's plan output into readtheplan's internal ResourceChange representation so the rest of the engine — risk classification, compliance mapping, agent gating, evidence envelopes — works identically regardless of the source tool.

Today readtheplan ships with CloudFormation and Kubernetes adapters. Adding a new adapter means Terraform and OpenTofu already work natively through terraform show -json output, but tools like Pulumi, AWS CDK, Crossplane, or Terragrunt need an adapter.

Why write one?

  • You use Pulumi or CDK and want readtheplan's risk analysis on your plans.
  • You have a custom IaC tool and want compliance gates and audit evidence.
  • You want to extend the type-map for CloudFormation or Kubernetes resources not yet covered.

The BaseAdapter interface

Every adapter extends the abstract BaseAdapter class from src/readtheplan/adapters/base.py. Four members are required: 

class BaseAdapter(ABC):

    @property
    @abstractmethod
    def adapter_name(self) -> str:
        """Unique name, e.g. 'pulumi' or 'cdk'."""
        pass

    @abstractmethod
    def can_handle(self, input_data: dict) -> bool:
        """Return True if input_data matches this tool's format."""
        pass

    @abstractmethod
    def extract_changes(self, input_data: dict) -> list[dict]:
        """Flatten the plan into a list of per-resource dicts."""
        pass

    @abstractmethod
    def normalize_change(self, raw_change: dict) -> ResourceChange:
        """Map one raw change dict to a ResourceChange dataclass."""
        pass

adapter_name

A short, kebab-case identifier unique to your adapter. Used as the registration key and surfaced in agent-gate output under the adapter field. Example: "pulumi", "aws-cdk", "crossplane".

can_handle(input_data) -> bool

Probe the raw plan dictionary for format-specific signatures. Be strict enough that you don't false-positive on other tools' JSON. CloudFormation checks for a "Changes" list or "old_template" and "new_template"; Kubernetes checks for "old_manifests" and "new_manifests", or a "resources" array with manifest kinds.

extract_changes(input_data) -> list[dict]

Extract a flat list of per-resource change dictionaries from the raw plan JSON. Each element is an adapter-normalized dict — it doesn't have to be a ResourceChange yet, but it should contain all the fields normalize_change needs (action, resource type, address, replacement metadata, etc.).

You can also attach an optional "_metadata" dict (containing "before" and "after" properties) that the rules engine uses for deep resource-specific escalation (e.g., IAM policy diff, S3 public access check, RDS version bump).

normalize_change(raw_change) -> ResourceChange

Convert one extracted change dict into a ResourceChange dataclass: 

@dataclass(frozen=True)
class ResourceChange:
    address: str        # Logical or physical resource identifier
    resource_type: str  # Normalized type, e.g. "aws_s3_bucket"
    actions: tuple      # One or more of ("create", "update", "delete")
    risk: str           # "safe" | "review" | "dangerous" | "irreversible"
    explanation: str    # Human-readable reason for the risk level

The actions tuple drives the risk taxonomy:

("create",)

→ safe

("update",)

→ review

("delete", "create")

→ dangerous

("delete",)

→ irreversible

The analyze() template method on BaseAdapter calls extract_changes → iterates → normalize_change → optionally _apply_resource_rules for deep risk escalation. You generally don't override analyze() — just provide the four abstract members.

Worked example: Pulumi adapter

Pulumi exports plan data as JSON via pulumi preview --show-secrets --json. The output has a "steps" array where each step describes a resource change. Below is a complete adapter implementation.

1. Create the file

Add a new file at src/readtheplan/adapters/pulumi.py: 

from __future__ import annotations

from typing import Any

from readtheplan.adapters.base import BaseAdapter
from readtheplan.plan import ResourceChange


class PulumiAdapter(BaseAdapter):

    _TYPE_MAP = {
        "aws:s3/bucket:Bucket":                "aws_s3_bucket",
        "aws:rds/instance:Instance":           "aws_db_instance",
        "aws:rds/cluster:Cluster":             "aws_rds_cluster",
        "aws:iam/role:Role":                   "aws_iam_role",
        "aws:iam/policy:Policy":               "aws_iam_policy",
        "aws:kms/key:Key":                     "aws_kms_key",
        "aws:lambda/function:Function":        "aws_lambda_function",
        "aws:ecs/service:Service":             "aws_ecs_service",
        "aws:ec2/securityGroup:SecurityGroup": "aws_security_group",
    }

    @property
    def adapter_name(self) -> str:
        return "pulumi"

    def can_handle(self, input_data: dict[str, Any]) -> bool:
        # Pulumi deployments always have a "steps" key with resource ops
        if "steps" in input_data and isinstance(input_data["steps"], list):
            return len(input_data["steps"]) > 0
        return False

    def extract_changes(self, input_data: dict[str, Any]) -> list[dict[str, Any]]:
        changes = []
        for step in input_data.get("steps", []):
            op = step.get("op", "").upper()
            urn = step.get("urn", "")
            # URN format: urn:pulumi:stack::project::type::name
            parts = urn.split("::")
            resource_type = parts[3] if len(parts) >= 4 else "Unknown"
            logical_id = parts[-1] if parts else urn

            # Extract before/after properties from detailed diff
            metadata = {}
            if "diffs" in step and "detailedDiff" in step.get("detailedDiff", {}):
                metadata = {
                    "before": step.get("oldState", {}).get("inputs", {}),
                    "after": step.get("newState", {}).get("inputs", {}),
                }

            changes.append({
                "Action": op,
                "LogicalResourceId": logical_id,
                "ResourceType": resource_type,
                "urn": urn,
                "_metadata": metadata if metadata else None,
            })
        return changes

    def normalize_change(self, raw: dict[str, Any]) -> ResourceChange:
        action = raw.get("Action", "UNKNOWN")
        resource_type = raw.get("ResourceType", "Unknown")
        logical_id = raw.get("LogicalResourceId", "<unknown>")
        urn = raw.get("urn", "")

        # Map Pulumi op codes to risk/actions
        risk = "review"
        actions = ("unknown",)
        explanation = f"Pulumi action '{action}' requires review."

        if action == "CREATE":
            risk = "safe"
            actions = ("create",)
            explanation = "Pulumi will create this resource."
        elif action == "UPDATE":
            risk = "review"
            actions = ("update",)
            explanation = "Pulumi will update this resource in place."
        elif action == "DELETE":
            risk = "irreversible"
            actions = ("delete",)
            explanation = "Pulumi will delete this resource."
        elif action == "DELETE-REPLACE":
            risk = "dangerous"
            actions = ("delete", "create")
            explanation = "Pulumi will replace this resource (destroy and recreate)."
        elif action == "CREATE-REPLACE":
            risk = "dangerous"
            actions = ("delete", "create")
            explanation = "Pulumi will replace this resource (create then destroy)."
        elif action == "READ":
            risk = "safe"
            actions = ("read",)
            explanation = "Pulumi will read an existing resource."

        normalized_type = self._normalize_resource_type(resource_type)
        address = urn if urn else logical_id

        return ResourceChange(
            address=address,
            resource_type=normalized_type,
            actions=actions,
            risk=risk,
            explanation=explanation,
        )

    def _normalize_resource_type(self, pulumi_type: str) -> str:
        if pulumi_type in self._TYPE_MAP:
            return self._TYPE_MAP[pulumi_type]
        if not pulumi_type or not isinstance(pulumi_type, str):
            return "unknown"
        # Fallback: aws:s3/bucket:Bucket -> aws_s3_bucket
        return pulumi_type.replace(":", "_").rsplit("/", 1)[-1].lower()

2. Register the adapter

Open src/readtheplan/adapters/__init__.py and add your import and registration call: 

from readtheplan.adapters.pulumi import PulumiAdapter

# ... existing registry code ...

register_adapter(PulumiAdapter())

The register_adapter() call makes the adapter available to detect_adapter(), which iterates the registry and returns the first adapter whose can_handle() returns True.

3. Wire the CLI (optional but recommended)

If your adapter should have its own CLI subcommand (like readtheplan cloudformation or readtheplan kubernetes), add it to the CLI entry point. The dedicated handler should load the JSON, call detect_adapter(), verify the adapter type, and invoke its analyzer. The general analyze and agent-gate commands remain Terraform/OpenTofu-specific.

How adapters register & auto-detect

The module src/readtheplan/adapters/__init__.py maintains an in-memory registry — a dict[str, BaseAdapter] keyed by adapter_name. 

_registry: dict[str, BaseAdapter] = {}

def register_adapter(adapter: BaseAdapter) -> None:
    _registry[adapter.adapter_name] = adapter

def get_adapter(name: str) -> BaseAdapter:
    return _registry[name]

def detect_adapter(input_data: dict) -> BaseAdapter | None:
    for adapter in _registry.values():
        if adapter.can_handle(input_data):
            return adapter
    return None

The flow works as follows:

  1. At import time, each adapter module is loaded and calls register_adapter(MyAdapter()).
  2. When a dedicated adapter command runs, its handler loads the JSON and calls detect_adapter(data).
  3. detect_adapter iterates every registered adapter, calling can_handle(data) on each.
  4. The handler verifies the detected adapter type, then calls that adapter's analyzer. The first registry match wins, so order matters if two adapters claim the same input.

Important: Make your can_handle() check precise enough that it won't accidentally claim Terraform, CloudFormation, or Kubernetes output. When in doubt, check for multiple format-specific keys. Order of registration in __init__.py determines priority.

Testing your adapter

Follow the test patterns in tests/test_cfn_adapter.py and tests/test_k8s_adapter.py. Create a new file tests/test_pulumi_adapter.py. Every adapter should cover:

Unit tests for can_handle

from readtheplan.adapters.pulumi import PulumiAdapter
from readtheplan.adapters import detect_adapter

def test_pulumi_can_handle():
    adapter = PulumiAdapter()
    data = {"steps": [{"op": "CREATE", "urn": "urn:pulumi:..."}]}
    assert adapter.can_handle(data) is True

def test_pulumi_rejects_cfn():
    adapter = PulumiAdapter()
    assert adapter.can_handle({"Changes": []}) is False
    assert adapter.can_handle({}) is False

Unit tests for normalize_change

def test_pulumi_normalize_create():
    adapter = PulumiAdapter()
    raw = {
        "Action": "CREATE",
        "LogicalResourceId": "my-bucket",
        "ResourceType": "aws:s3/bucket:Bucket"
    }
    rc = adapter.normalize_change(raw)
    assert rc.actions == ("create",)
    assert rc.risk == "safe"
    assert rc.resource_type == "aws_s3_bucket"

def test_pulumi_normalize_delete_replace():
    adapter = PulumiAdapter()
    raw = {
        "Action": "DELETE-REPLACE",
        "LogicalResourceId": "my-role",
        "ResourceType": "aws:iam/role:Role"
    }
    rc = adapter.normalize_change(raw)
    assert rc.actions == ("delete", "create")
    assert rc.risk == "dangerous"

Integration test with extract_changes + analyze

def test_pulumi_analyze_rules_escalation():
    adapter = PulumiAdapter()
    data = {
        "steps": [
            {
                "op": "DELETE",
                "urn": "urn:pulumi:prod::app::aws:rds/instance:Instance::my-db",
            }
        ]
    }
    changes = adapter.analyze(data, tool_name="Pulumi")
    rc = changes[0]
    # The rules engine should escalate RDS deletion to irreversible
    assert rc.risk == "irreversible"
    assert "RDS" in rc.explanation

Fixture-based tests

Save a sample Pulumi preview JSON to tests/fixtures/pulumi_preview_mixed.json and write a test that validates the full agent-gate contract: 

import json
from pathlib import Path

def test_pulumi_fixture_gate_contract():
    fixture = Path("tests/fixtures/pulumi_preview_mixed.json")
    data = json.loads(fixture.read_text())
    adapter = PulumiAdapter()
    changes = adapter.analyze(data, tool_name="Pulumi")
    assert len(changes) > 0
    # Verify risk classifications on each change
    for c in changes:
        assert c.risk in ("safe", "review", "dangerous", "irreversible")

Detection registration test

def test_detect_pulumi_adapter():
    data = {"steps": [{"op": "CREATE", "urn": "..."}]}
    adapter = detect_adapter(data)
    from readtheplan.adapters.pulumi import PulumiAdapter
    assert isinstance(adapter, PulumiAdapter)

Run all adapter tests with: 

pytest tests/test_pulumi_adapter.py -v

Submitting an adapter as a PR

Once your adapter is implemented and tested, open a pull request against the readtheplan repo. Follow these guidelines:

Checklist

  • One adapter per PR. If you're adding multiple adapters, submit them separately for focused review.
  • Include tests. All unit tests for can_handle, normalize_change, and at least one integration test with extract_changes + analyze.
  • Include a fixture. A small, anonymized plan JSON in tests/fixtures/ for your tool, with a test that validates the agent-gate contract.
  • Update __init__.py. Import and register your adapter. Add it to __all__.
  • Update the type map. If your adapter maps resource types, include coverage for the most common resources in your tool.
  • No regressions. Run the full test suite before opening the PR: pytest.

PR description template

## Summary

Adds a new adapter for [Tool Name] — [one-line description].

## Changes

- `src/readtheplan/adapters/[tool].py` — new adapter file
- `src/readtheplan/adapters/__init__.py` — registration and export
- `tests/test_[tool]_adapter.py` — unit and integration tests
- `tests/fixtures/[tool]_sample.json` — example plan fixture

## Testing

- `pytest tests/test_[tool]_adapter.py -v` — all tests pass
- `pytest` — full suite passes, no regressions

## Adapter detail

| Field          | Value            |
|----------------|------------------|
| `adapter_name` | `[tool]`         |
| Input format   | `[tool] plan`    |
| CLI command    | `detect` / custom |

## Type map coverage

Lists the resource types currently mapped in the adapter.

Review expectations

Maintainers will review:

  • Detection accuracy — does can_handle correctly identify your tool's format without false-positives?
  • Risk correctness — are create/update/delete/replace mapped to the right risk tiers?
  • Type normalization — are resource types mapped to the canonical aws_* naming convention?
  • Test coverage — are edge cases (unknown actions, missing fields, empty plans) covered?
  • Fixture quality — is the fixture realistic and representative?
